## 11.1.0 (2026-10-30) \{#1110}

### Minor changes

- Add the optional `spaceAware` field (`boolean`) to `SchemaDefinitionRestDto`. When `true`, space-based access control is enabled for the schema. It only applies when `multiObject` is `true` and `ordered` is `false`.
- Add the optional `maxObjectCount` field (`number`) to `SchemaConstraintRestDto`, and the `MULTI_SCOPE_MAX_OBJECT_COUNT` value to its `type` union and to `SchemaConstraintRestDtoType`. It limits the number of objects over all scopes. Only additions are denied, and updates and deletions are always allowed. Add a case for the new type to any exhaustive `switch` over these types.
- Add the required `metadata` field to `Extension` and `ExtensionUploadResponseDto`, typed as the new `ExtensionMetadata` and `ExtensionUploadResponseDtoMetadata` string maps. It holds additional non-asset information about the extension as key-value pairs. Objects you build by hand for these types, such as test fixtures and mocks, must now include `metadata`.
- Add the `PROBLEM_RESOLUTION_PATH_RULES` value to `AssetInfoDtoType` and to the `type` union of `AssetInfoDto`. Add a case for it to any exhaustive `switch` over these types.
- Add the `TRACEROUTE` value to `SyntheticMultiProtocolMonitorStepDtoRequestType` and to the `requestType` union of `SyntheticMultiProtocolMonitorStepDto`. The API description still says only ICMP, TCP and DNS are currently supported. Do not rely on `TRACEROUTE` until the service supports it.
- Update the documented limit for `primaryGrailTags` on the synthetic HTTP, browser and multi-protocol monitor request and response types from 10 to 20 tags. This is a documentation change only. The TypeScript signatures are unchanged.

### Patch changes

- Updated the minimum required versions of `@dynatrace-sdk/http-client` (`^1.5.2`) and `@dynatrace-sdk/shared-errors` (`^1.1.0`).
