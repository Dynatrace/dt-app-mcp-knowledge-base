## 3.0.0 (2026-10-05) \{#300}

### Major changes

- BREAKING: Remove `UserSessionApplicationType.AmpApplication` and the `'AMP_APPLICATION'` value from `UserSession.applicationType`. Remove any code that references either one.

### Minor changes

- Add `'ruby'` to the `include` option of the agent installer methods in `DeploymentClient`, and add `Ruby` to the matching `*QueryIncludeItem` enums.
- Add `'RUST'` to the `moduleType` of `ManualApplication` and `ModuleInfo`, to the `technologyModuleType` option of `OneAgentOnAHostClient.getHostsWithSpecificAgents`, and add `Rust` to the matching enums.
- Add `'python'`, `'go'` and `'DotNet'` to the `techtype` option of `DeploymentClient.getLambdaLayerBuildUnits`.
- Add `DeploymentClient.getAgentProcessGroupingConfig`.
- Add the `capabilities: string[]` field to `Node` and `NodeCollectionElement`.
- Add `'UNKNOWN_DOC_LOADED'` to `UserSession.reasonForNoSessionReplay` and `UserSessionReasonForNoSessionReplay.UnknownDocLoaded`.

### Patch changes

- Mark several `DeploymentClient`, `RumJavaScriptTagManagementClient` and `SyntheticMonitorsClient` methods as `@deprecated`.
- A `package.json` containing `{"type":"module"}` is now emitted into the `esm/` output directory of each published package. This allows Node.js and bundlers to correctly identify the ESM output as ES modules without requiring the `.mjs` file extension.
