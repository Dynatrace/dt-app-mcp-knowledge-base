### CronTrigger

Runs the workflow on a cron schedule, evaluated in the schedule's `timezone`.

Use it for recurring patterns that `time` and `interval` can't express, e.g. weekdays
only or the first day of each month. The schedule's `rule` and the date fields of
`filterParameters` don't apply to cron triggers.

| Name            | Type   | Description                                                                                                                                                                                                                                                                                                                      |
| --------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| cron (required) | string | Cron expression with exactly 5 fields: minute (0-59), hour (0-23), day of month (1-31), month (1-12 or JAN-DEC) and day of week (0-7 or SUN-SAT, 0 and 7 are Sunday). A seconds field isn't supported, so the shortest cadence is one minute. Supports `*`, `,`, `-` and `/` (e.g. `* /15`).<br /><br />**Example:** `0 0 * * *` |
| type (required) | "cron" |                                                                                                                                                                                                                                                                                                                                  |

### IntervalTrigger

Runs the workflow every `intervalMinutes`, optionally only within a daily time window.

Unless `filterParameters.earliestStart` is set, the first run is one interval after
the schedule is saved, not immediately. A run that would fall outside the time window
moves to the next `betweenStart`, and runs repeat every `intervalMinutes` from there.
Combine it with the schedule's `rule` or `filterParameters` to restrict the days it
runs on. Cadences longer than 12 hours aren't supported. `time` or `cron` triggers
cover calendar-based ones, e.g. daily or weekly, but not e.g. every 18 hours.

| Name                       | Type           | Description                                                                                                                                                                                                                                                                                 |
| -------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| betweenEnd                 | null \| string | End of the daily time window in 24-hour `HH:MM` format, in the schedule's `timezone`, inclusive. Without `betweenStart`, the window starts at `00:00`. If it's earlier than `betweenStart`, the window spans midnight, e.g. `22:00` to `02:00`.<br />Pattern: `^([0-1]\d\|2[0-3]):[0-5]\d$` |
| betweenStart               | null \| string | Start of the daily time window in 24-hour `HH:MM` format, in the schedule's `timezone`. Without `betweenEnd`, the window lasts until the end of the day.<br />Pattern: `^([0-1]\d\|2[0-3]):[0-5]\d$`                                                                                        |
| intervalMinutes (required) | number         | Minutes between runs, from 1 to 720 (12 hours).<br /><br />**Minimum:** `1`                                                                                                                                                                                                                 |
| type (required)            | "interval"     |                                                                                                                                                                                                                                                                                             |

### OnceTrigger

Runs the workflow exactly once, at `at` in the schedule's `timezone`.

The time must be in the future. The schedule's `rule` and the date fields of
`filterParameters` don't apply to once triggers.

| Name            | Type   | Description                                                                                                                                                                                                                                                     |
| --------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| at (required)   | string | Local date and time in ISO 8601 format `YYYY-MM-DDTHH:MM:SS`, without a UTC offset or `Z`. It's interpreted in the schedule's `timezone`.<br /><br />**Example:** `2099-12-25T14:30:00`<br />Pattern: `^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}$` |
| type (required) | "once" |                                                                                                                                                                                                                                                                 |

### ScheduleFilterParameters

Restricts the dates on which a `time` or `interval` trigger runs.

Dates are `YYYY-MM-DD` in the schedule's `timezone`. Apart from `count`, filter
parameters don't apply to `cron` and `once` triggers.

| Name              | Type                   | Description                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| count             | number                 | On a saved schedule: the number of remaining runs. After the last one, the schedule is deactivated. Applies to all trigger types. If omitted, a saved schedule has no limit and runs indefinitely. In the schedule preview: the number of upcoming runs to return, at most 50. If omitted, 10 are returned.<br /><br />**Minimum:** `1` |
| earliestStart     | null \| string         | Date of the first possible run in `YYYY-MM-DD` format. No run happens before this date.                                                                                                                                                                                                                                                 |
| earliestStartTime | string                 | Time of day in 24-hour `HH:MM` format that, together with `earliestStart`, marks the first possible run of an `interval` trigger. Ignored without `earliestStart` and for `time` triggers.<br /><br />**Default:** `00:00`<br />Pattern: `^([0-1]\d\|2[0-3]):[0-5]\d$`                                                                  |
| excludeDates      | null \| Array\<string> | Dates in `YYYY-MM-DD` format on which the trigger doesn't run. Must lie between `earliestStart` and `until` and must not overlap with `includeDates`.                                                                                                                                                                                   |
| includeDates      | null \| Array\<string> | Dates in `YYYY-MM-DD` format to add to the days selected by the schedule's `rule`. On these dates the trigger runs at its usual times even if the rule doesn't select them, so it only has an effect together with `rule`. Must lie between `earliestStart` and `until` and must not overlap with `excludeDates`.                       |
| until             | null \| string         | Date of the last possible run in `YYYY-MM-DD` format, inclusive. Must not be before `earliestStart`.                                                                                                                                                                                                                                    |

### TaskConditionOptionStates

Required final state per predecessor, keyed by task name. Every key must also be in `predecessors`. SUCCESS, ERROR: exactly that state. OK: success or skipped. NOK: error or cancelled. ANY: any final state. Predecessors without an entry default to OK. If a predecessor was discarded, this task is discarded too, even with ANY.
